# EDA 布线讨论中的经验与候选状态

这是 2026-10-12 保存的构思经验，不是文献综述或已完成实验的报告。迁移到新课题时，不要把用户在本次对话中的偏好变成对所有研究的禁令。

## 已有能力要如实重建

[GR-Evolve](https://arxiv.org/html/2604.22234v1) 已展示对全局布线源码进行设计适配进化，并用详细布线后的指标反馈。其空间包括成本函数、启发式、控制流和数据结构；允许暂时退步、保留版本历史，讨论 warm start，并出现按线网特征调整网格等机制。

因此，不要声称它只能调参数、禁止条件策略、只能单处变异、只接受改进、不能改表示或完全没有迁移经验。[GoalEvolve](https://arxiv.org/html/2608.16733v1) 也已有目标与阶段证据、机制组合、失败经验等设计；“加入记忆、反思或诊断”本身不足以定义未解决的问题。

这些概述用于防止本次已出现的稻草人判断，不能替代日后针对版本与研究范围的核验。

## 用户真正希望的构思方式

- 从“源码进化可行”向下一阶段问题推进，而非在源码内部任意挑模块。
- 大方向之间保持同级；先说清问题，再选择机制与实现落点。
- 每个方向说明具体借鉴了哪个领域的什么问题和机制，不能只有论文名。
- 一句话同时包含问题、原因与解决方式，配通俗例子；避免压缩到失去语义。
- 构思阶段不要预演审稿答辩；允许大胆假说，也允许有依据地反驳用户。
- 概念分析可以先于实验，不必先配置 API 或因只有 Windows 就压缩想象范围。

## 已形成的三个候选，尚未完成选题

### 共同进化全局与详细布线的决策边界

原理支点：全局方案的最终价值取决于详细布线如何实现；固定搭档可能限制能发挥价值的改动。

方向包含谁决定什么、传递哪些信息、什么可以重考虑。双方算法与接口可以兼容地作为实现手段，不是必须二选一。不能未经讨论就缩为详细布线某个冲突修复模块。

### 共同发现问题的等价表达与求解方法

原理支点：同一物理任务可有不同计算表达，算法能利用的结构可能不同。

必须明确等价保持什么；不能把删掉合法路线的简化叫作严格等价。GR-Evolve 已允许改数据结构，这里提出的是显式研究表达与求解之间的关系，不能声称新打开了它绝对禁止的能力。

### 发现带数学保证的布线算法

原理支点：“先搜索哪里”与“永久排除哪里”需要不同依据；可研究创新策略与可验证保证如何配合。

这是更强的候选研究目标，不是已有方法错误的证据。要先定义希望保证的性质与问题类别，不能将最终 DRC 合法直接等同于不漏解或全局最优。

以上三个方向是待比较的候选，不是已证明新颖、已验证有效或已被用户最终选定的课题。

## 应保留的失败教训

- 曾用 ResNet 类比泛泛的“可进化性”，但没有目标领域的退化现象或已知参照。正确修正是补清证据条件，不能继续以类比替代发现。
- 曾把“增加算力能产生多少收益”直接列成大方向，缺少机制。正确修正是寻找共享计算、评价结构等具体原理，而非判定所有效率研究没有学术价值。
- 曾提出经验保留与知识飞轮，用户认为只是 memory 包装。应说明什么决策或学习机制改变；这不意味着 memory、迁移或元学习普遍没有研究价值。
- 曾从系统合作方向突然跳到详细布线控制层，造成层级混乱。先解释父问题与关系，再向下展开。
- 用户质疑“要知道全局最优才能证明搜索受限”时，应该以 ResNet 的已知可构造参照作有依据的反驳，同时承认尚未观察到布线的对应现象。
